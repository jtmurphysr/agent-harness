## Context

Apple Music has a two-token auth system:

- **Developer Token** (JWT, ES256) — already implemented in `auth/apple_auth.py`. Grants catalog read access. ISRC lookups work with this alone.
- **Music User Token** — required for ALL user library operations: creating playlists, adding tracks, reading personal library. Cannot be obtained server-side. Requires explicit user authorization via MusicKit JS in a browser.

Currently `clients/apple_client.py._get_headers()` only sends the developer token:
```python
def _get_headers(self) -> dict[str, str]:
    return {
        "Authorization": f"Bearer {self._auth.get_token()}",
        "Content-Type": "application/json",
    }
```

This causes 403 Forbidden on all `/v1/me/library/*` endpoints.

## What Needs to Be Built

### 1. `auth/music_user_token.html`

A self-contained HTML page using MusicKit JS that:
- Loads MusicKit JS from Apple's CDN: `https://js-cdn.music.apple.com/musickit/v3/musickit.js`
- Configures MusicKit with the developer token (user pastes it in)
- Prompts user authorization via `MusicKit.getInstance().authorize()`
- Displays the resulting Music User Token prominently for copying
- Requires no server — opens directly in browser via `file://` or `python3 -m http.server`

The page must:
- Accept the developer token as input (text field) — user generates it via `auth/get_music_user_token.py`
- Show clear step-by-step instructions
- Display the Music User Token in a copyable text box after authorization
- Work in Safari and Chrome

### 2. `auth/get_music_user_token.py`

A standalone script that:
- Loads env vars from `.env`
- Generates and prints the current developer token via `AppleAuthClient().get_token()`
- Instructs the user to paste it into `auth/music_user_token.html`

```bash
# Usage:
python auth/get_music_user_token.py
# Output:
# Developer token: eyJhbGci...
# 1. Open auth/music_user_token.html in your browser
# 2. Paste the token above into the Developer Token field
# 3. Click Authorize and sign in with your Apple ID
# 4. Copy the Music User Token and add to .env:
#    APPLE_MUSIC_USER_TOKEN=<token>
```

### 3. Update `auth/apple_auth.py`

Add Music User Token support to `AppleAuthClient`:

```python
def __init__(self) -> None:
    # existing fields...
    self._music_user_token: str | None = os.environ.get("APPLE_MUSIC_USER_TOKEN")


def get_music_user_token(self) -> str | None:
    """Return Music User Token from env, or None if not configured."""
    return self._music_user_token
```

### 4. Update `clients/apple_client.py`

Update `_get_headers()` to include Music User Token when available:

```python
def _get_headers(self) -> dict[str, str]:
    headers = {
        "Authorization": f"Bearer {self._auth.get_token()}",
        "Content-Type": "application/json",
    }
    music_user_token = self._auth.get_music_user_token()
    if music_user_token:
        headers["Music-User-Token"] = music_user_token
    return headers
```

## Domain Warnings

⚠️ **MusicKit JS requires a valid developer token to initialize** — the token must be passed to `MusicKit.configure()` before calling `authorize()`. Use the token generated by `get_music_user_token.py`.

⚠️ **Music User Tokens are long-lived** — once obtained, store in `.env` as `APPLE_MUSIC_USER_TOKEN`. No expiry management needed for CLI use.

⚠️ **MusicKit JS authorization only works from HTTP/HTTPS origin** — opening `music_user_token.html` directly via `file://` may fail in some browsers. Instruct user to run `python3 -m http.server 8080` in the `auth/` directory and open `http://localhost:8080/music_user_token.html`.

⚠️ **`get_music_user_token()` returns `None` if env var not set** — `_get_headers()` must handle `None` gracefully, not crash. The client must still work for catalog-only operations (dry-run ISRC resolution) when Music User Token is absent.

⚠️ **Do NOT hardcode the developer token in the HTML file** — it must be user-supplied via input field to avoid leaking credentials into the codebase.
