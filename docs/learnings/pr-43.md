# Learning: PR #43 — one push, zero content changes, six days blocked by two gate defects

The agent wrote 110 tests for the two Python gates, pushed once, and never touched the
branch again. The PR then sat for **six days**. Both things that blocked it were defects
in the harness's own gates, and both were fixed on `main` by a human — not in this diff:

| When | What blocked it | Where it was fixed |
|---|---|---|
| 09-21 16:31 | `unresolved no-files-section #36` — issue #36 as dispatched had no FILES sections | issue #36 body, edited 09-27 14:26 |
| 09-27 14:27 | `fail claimed-not-changed .claude/agents/` | `scripts/check-spec-conformance.sh`, commit `f9cf18d` (PR #48) |
| 09-27 15:11 | — | branch force-pushed (rebase onto the fixed `main`, content identical) |
| 09-27 15:18 | — | merged, 8 seconds after the last reviewer finished |

Every other check was green on the first push: Lint & Types, Tests, Harness Structure,
Hook Guards, Workflow Change Guard, and all three reviewers at WARN. **The single
force-push carries no content change** — the commit's author date is 09-21T16:30 and its
commit date is 09-27T15:11.

This is the pr-30 shape for the third time: *a required-iteration cycle in which the
agent's output was never the thing that changed.* See `docs/learnings/pr-30.md`
("the gate refused its own PR, twice, and both refusals were right"). The difference is
that this time only one of the two refusals was right, and neither was about the diff.

## What Was Specified

Issue #36, filed by the GC entropy pass on 2026-09-21: `scripts/` is invisible to
coverage. With no `__init__.py`, coverage's file walk never descends into the directory,
so only a script some test actually imports ever reaches a report. Exactly one did.
The two that did not are the gates — `validate_harness.py` (a required status check on
`main`) and `check_coverage_floor.py` (the per-file floor gate). **Neither had a single
unit test, and neither was subject to the floor it enforces.**

The issue named the branches an end-to-end CI invocation never reaches, per function:
`is_stub_only`'s stub forms and its fail-safe direction, `load_coverage_omit_list`'s
`None` paths, `check_coverage_omit_drift` against globs and `PERMANENT_OMITS`,
`lint_file`'s cross-boundary/untracked/`SyntaxError` cases, `run_lint`'s
`files_checked == 0`, Pass 1b's new-cycle and stale-`KNOWN_CYCLES` paths,
`check_rendered_agents`' seven outcomes, and — the one the floor gate exists for —
`file_percentages` reading `percent_covered` and never `percent_covered_display`,
asserted on a fixture where the two disagree.

Two explicit prohibitions: do **not** resolve the invisibility by adding `scripts/*` to
`[tool.coverage.run] omit`, and treat `scripts/__init__.py` as a deliberate decision
(it would break the mypy exclusion that exists *because* the directory is not a package),
not a side effect.

**As dispatched at 16:10, issue #36 had no `## Files to Create`, no `## Files to Modify`,
no `## Out of Scope` and no `## Acceptance Criteria` section.** Those four sections were
added to the issue body on 2026-09-27 at 14:26 — six days after dispatch, with the PR's
diff already visible.

## Delta Analysis

**Scope: exact.** Two files created, zero modified. When the FILES sections were
retrofitted six days later, `Files to Create` named those two files and `Files to Modify`
was empty under a "Read for context only" header. The agent, given only prose, produced
precisely the file list a human wrote down afterwards.

That is the good news and the caveat in one sentence: **the spec-conformance check on
this PR was circular.** It measured the diff against a FILES list drafted with the diff
on screen. The scope verdict here is evidence about the agent's judgement from prose,
not evidence the gate constrained anything.

**Coverage of named branches: complete**, including the two the issue flagged as the
point of the exercise (`files_checked == 0`, and raw float vs display rounding).

**Three real defects shipped**, all found by the engineer reviewer, all landing 8 seconds
before auto-merge:

1. `tests/test_check_coverage_floor.py:178` —
   `test_print_table_width_never_shrinks_below_the_header` **cannot fail.**
   `f"{'Path':<{width}}"` pads but never truncates, so `"Path" in out` holds with or
   without the `+ [len("Path")]` guard it claims to test. Verified against the merged
   source. A PR whose premise is *"a check that cannot fail is a decoration"* shipped a
   decoration.
2. `tests/test_check_coverage_floor.py:139` —
   `test_print_exceptions_says_none_when_empty` reads the live `ccf.EXCEPTIONS` instead
   of monkeypatching it to `{}`. The first legitimate use of the gate's documented
   exemption escape hatch breaks an unrelated test, with no reviewer in the loop to
   connect the two.
3. The PR body's per-file counts are wrong: 76/34 claimed, 79/24 on disk. The 110 total
   is right. Nothing verified the split before it became the permanent record.

**Two structural findings from architect and sre, neither filed as an issue:**

- Coverage of both gates now rests entirely on an import statement in a test file, with
  nothing declaring that dependency. `check_coverage_floor.py` can only judge paths
  present in `coverage.json`, so deleting or renaming either test file silently restores
  #36's invisibility **with the floor gate still exiting 0**. The suggested fix is a
  `REQUIRED_MEASURED` set checked before the shortfall loop.
- `pyproject.toml:120-123` says `scripts/` is excluded from mypy because the directory is
  not a package. mypy's `exclude` does not stop import following, and `tests/` now does
  `from scripts import ...`, so `mypy --strict .` reaches both gate scripts. The comment
  in `pyproject.toml` no longer describes what the config does.
- `scripts/validate_harness.py:195` still lists `"scripts/*"` in `PERMANENT_OMITS`, so
  Pass 2 would bless the exact resolution #36 forbade. The new
  `test_this_repo_does_not_omit_scripts` is now the *only* thing preventing it — which
  works, but puts the rule in a test rather than in the linter that owns it.

## Learnings

### For Future Issue Specs

**An issue with no FILES sections is undispatchable, and this is the third time.**
Issues #28, #29 and now #36 were all dispatched as prose and all produced
`unresolved no-files-section`. `docs/learnings/pr-30.md` already carries the fix as a
suggested action — *"Put FILES TO CREATE / FILES TO MODIFY in the issue template as
required headings"* and *"Sweep the dispatch queue for FILES sections"* — filed on
2026-09-20, unactioned when the GC pass filed #36 the next day. The cost this time was
six days of wall-clock on a PR that was correct on its first push. **A suggested action
that survives three occurrences is not a suggestion; promote it or delete it.**

**Retrofitting the spec after the PR opens makes the gate a mirror.** Issue #36's FILES
sections were written on 09-27 with PR #43's diff visible. The `pass` verdict that
followed proves the two lists match; it does not prove the agent stayed in a scope
anyone had declared. `docs/learnings/pr-30.md`'s *"record the issue body at dispatch
time"* action is what closes this, and it is also still open. Until then, treat every
`scope` verdict on a PR whose issue was edited mid-flight as uninformative, and say so in
the learning rather than counting it as a clean pass.

**An issue that names branches per function is the reason this went right.** #36 did not
say "add tests". It listed, per function and with line numbers, the inputs no CI run had
ever supplied, and it named the one assertion that mattered (`84.69` vs `"85%"`). The
delivered file covers that list almost item for item. This is the highest-fidelity
prose-only spec in the repo so far; issues for test-debt work should be written in this
shape.

**State the second-order consequence of the obvious fix, and ask for a decision rather
than forbidding it.** #36 said `scripts/__init__.py` "should be considered deliberately
rather than as a side effect" and explained the mypy coupling. The agent considered it,
declined it, wrote down an ordering constraint nobody had articulated (it must land after
`backfill_learnings.py` has tests), and filed that constraint as #42. A flat "do not add
`__init__.py`" would have produced compliance and no reasoning.

### For Future Domain Warnings

**A test-only PR must name the module it tests, and until 09-27 that was a gate
failure.** `claimed-not-changed` treated every inline backticked path in a PR body as a
claim about the diff. PR #43's body carried fifteen such tokens — unavoidably, because a
PR that *adds tests for* a module has to name that module while not modifying it. The
gate's own measured record was six firings and zero true positives (four on #31, one on
#40, one on #43). Fixed in `f9cf18d`: only the `## Files` section is held to the diff;
prose may name anything. **Recording it here rather than as an AGENTS.md rule, because
the cause is fixed — a rule for it would be an archive entry, and that section is law,
not history.**

**Coverage acquired by import is coverage with no declared owner.** Both gates are
measured because two test files import them. Nothing states that requirement, and the
floor gate cannot notice a file that has vanished from the report — absence reads as
silence, not as a shortfall. Any future "make X visible to coverage" issue should require
the reverse assertion too: a named set of paths that *must* appear in `coverage.json`,
checked before the per-file loop.

**`exclude` in a type checker is not a boundary.** mypy follows imports into excluded
directories; the moment a checked file imports an excluded one, the exclusion is decor.
Worth remembering the next time a config comment explains *why* a tree is excluded — the
comment can be true about the intent and false about the effect.

### For AGENTS.md

Two edits made, both minimal:

1. **LESSON 4** gains a third step: an issue you file is a dispatch spec, so it needs
   FILES TO CREATE / FILES TO MODIFY headings or the spec-conformance gate fails closed
   on the PR that answers it. The GC entropy pass is an agent, #36 was its issue, and
   this is the third occurrence.
2. **LESSON 10** gains a paragraph generalising past defaults: an assertion that holds
   with the mechanism deleted proves nothing, whether the mechanism is a default or a
   `max(..., len("Path"))` guard. The check is mechanical — delete the guard, re-run the
   test, and if it still passes the test is decoration.

Deliberately **not** added: anything about `claimed-not-changed` and prose backticks.
The gate now scopes itself to the Files section, so a rule would describe a world that no
longer exists.

### Reusable Patterns

**Prove ordering with an exit code, not a mock.**
`test_main_rejects_an_exception_with_no_tracking_issue_before_any_io` asserts exit 1
against an input path that does not exist. If the self-check ran after the I/O the result
would be 2. The assertion *is* the ordering proof, with no patching and nothing to keep
in sync. Reach for this whenever "X must happen before Y" and X and Y have distinguishable
failure modes.

**Forbid a field with an AST walk, not a comment (LESSON 11, extended to fields).**
`test_percent_covered_display_is_never_read` parses the module, strips docstrings —
necessary, because the docstrings legitimately *name* the forbidden field — unparses, and
fails if the name survives. Previous applications of LESSON 11 used `inspect.getsource`
and substring checks, which the explanatory comment defeats. The strip-docstrings-then-
unparse variant is the version to copy when the thing being forbidden must still be
discussed in prose.

**Drive module-level relative paths with `chdir`, not by rewriting globals.**
`validate_harness.py` resolves `REPO_ROOT = Path(".")`, `AGENTS_DIR`, `TEMPLATES_DIR` at
call time. The test file builds a synthetic tree in `tmp_path` and `monkeypatch.chdir`s
into it, so the real resolution logic runs. Monkeypatching the globals instead would have
covered the lines while proving nothing about path handling.

**Guard leaked process state at the source it leaks from.** `check_rendered_agents`
appends to `sys.path` on every call; the tests absorb it with a `sys_path_guard` fixture.
The architect's note stands: a fixture that cleans up after production code is a finding
wearing a fixture's clothes. Write the fixture *and* file the leak.

**A reviewer WARN on an auto-merged PR has eight seconds to matter.** The engineer's
review completed at 15:18:14 and the merge landed at 15:18:22. Nobody acts on those
findings unless someone files them afterwards — #46 exists for PR #31's WARNs and is the
precedent. Three real defects from this PR (the tautological test, the live-`EXCEPTIONS`
coupling, the `REQUIRED_MEASURED` gap) are in comments and in this file, and nowhere else
yet.
