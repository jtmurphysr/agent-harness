# Learning: PR #40 — the diff was right on the first push; the prose around it was not

One commit, pushed 17 minutes after dispatch, never amended. Scope exactly matched the
issue's file list, both declared causes were fixed, and the agent corrected a technical
error in the issue's own suggested fix. The PR then sat for **seven days**, and when it
finally landed all three reviewers returned WARN — not about the templates, but about
the PR body's claims and the reach of the new test.

This is the `pr-30` / `pr-43` shape a fourth time: **a required-iteration cycle in which
the agent's output was never the thing that changed.** Both blockers were harness
defects, both were fixed on `main` by someone else, and the single force-push carries no
content change. See `docs/learnings/pr-43.md`, which stalled six days on the identical
pair and already names PR #40 as one of the `claimed-not-changed` false positives.

## What Was Specified

Issue #37, from the GC entropy pass on 2026-09-21. `.claude/agents/engineer.md` — the
file Claude Code actually loads — rendered its three invariants as one physical line,
its seven sharp edges as one physical line, and numbered the invariants **1, 3, 5**.
Same in `architect.md` and `sre.md`, and in every generated project, because the defect
is in the shipped templates.

The issue diagnosed both causes precisely and located them:

1. **`trim_blocks=True`** (`renderer/compose.py:47-51`) deletes the newline immediately
   following a block tag. Every loop ended its item line with `{% endif %}{% endfor %}`,
   so the separator *was* the newline being deleted.
2. **`loop.index` counts the unfiltered list**, because the severity filter was an
   `{% if %}` inside the loop rather than a `selectattr` on the `for` expression.

It offered two resolutions, recommended the local one, declared `renderer/compose.py`
**read-only on purpose** — "if the fix genuinely requires changing `trim_blocks`, say so
on this issue rather than widening scope" — and explained why nothing caught the bug:
`test_templates.py` asserts on the *templates*, and `validate_harness.py` Pass 3 diffs
rendered output against a fresh render of the same templates, so it is self-consistent
by construction no matter how mangled both sides are.

**As dispatched at 16:11, issue #37 had no FILES sections.** They were added later, with
the diff on screen.

## What Was Delivered

Seven files, +501 / −76, one commit. Exactly the seven the (retrofitted) FILES sections
name — three templates, three rendered agents, one new test class.

- Block tags moved onto their own lines; `+%}` where a tag must close a content line.
- The severity filter moved into the `for` expression:
  `invariants | selectattr('severity', 'in', [...])`. Engineer now reads 1, 2, 3.
- A Jinja comment at the top of each of the three templates stating the layout rule.
- `.claude/agents/*.md` re-rendered; template `version` bumped 1.0.0 → 1.0.1.
- `TestRenderedListShape` in `tests/test_render.py` — 10 functions, 18 parametrized
  cases, rendering the **real** `templates/` against a fixture whose seven invariants
  have interleaved severities, so a `loop.index` regression prints a gapped sequence.

Three things the agent got right that are worth naming:

- **It corrected the issue.** #37 suggested `{%+ if %}`; that is the `lstrip_blocks`
  modifier. `+%}` is the one that preserves the trailing newline. The agent found this,
  used the right form, and said so explicitly rather than silently diverging.
- **It honoured the read-only boundary.** `renderer/compose.py` was not touched and
  `trim_blocks` stayed on, per the issue's recommended option.
- **It fixed two defects beyond the three lists "Done when" named** — the
  `{% if %}`-guarded checklist bullets and the lost blank line before
  `**Key abstractions:**` — correctly identifying both as the same defect, not as scope
  creep. Out-of-scope findings were filed as **#39**, searched first per LESSON 4.

## Delta Analysis

**Scope: exact — but the verdict is circular.** Seven files changed, seven files listed.
Issue #37 was dispatched as prose and its FILES sections were retrofitted after the diff
existed, so the eventual `scope` pass measures the diff against a list drawn from it.
`docs/learnings/pr-43.md` recorded this same caveat for #36 the day before. It is
evidence about the agent's judgement from prose; it is not evidence a gate constrained
anything.

**One acceptance criterion was unsatisfiable as literally written.** It asked that "the
five declared invariants render as five separate lines numbered 1–5." Engineer's
severity filter selects three of the five, so the correct fix renders 1–3 — which is
what Cause 2 and the PR title both describe. The agent delivered the right thing and the
criterion was never reconciled on the issue.

**Four real problems shipped, none of them in the templates:**

1. **The propagation claim is false, and it is the PR's own headline section.** The body
   devotes a "Template version bump — please read" section to the fleet effect of
   1.0.0 → 1.0.1. Verified against the merged tree: `cli/render.py:61,104` writes the
   lock to `output_dir / "templates_lock.yml"` where `output_dir` is `.factory/agents/`
   (`cli/init.py:52,79`), while `cli/sync.py:184` reads `.factory/templates_lock.yml`.
   The 404 path returns `{}` and `_find_template_updates` skips every template — no
   upgrade PR is ever opened. Where a lock *is* found, `_update_templates_lock_on_branch`
   (`cli/sync.py:323-365`) ships only the lockfile: the project is marked v1.0.1 while
   its render stays collapsed, and because `_find_template_updates` compares lock-vs-
   current only, that **permanently suppresses the upgrade offer**. The claimed rollout
   path does not merely fail; running it would make the defect unfixable by the same
   mechanism. All three reviewers found this independently.
2. **The fence covers one of five surfaces.** `SHAPE_CONTEXT` (`tests/test_render.py:660`)
   pins `surface: "server"`. This PR rewrote the whitespace control of every per-surface
   branch in `sre.template.md` and `architect.template.md` — including the "no rollback
   mechanism" and "no server-side recovery" warnings — and no test renders
   mobile/cli/library/embedded. A re-collapse in those arms ships to generated projects
   undetected. Also found by all three reviewers.
3. **The vacuity claim is false.** "Thirteen cases … all thirteen fail against the
   pre-change templates" — there are 10 functions and 18 cases, and at least
   `test_section_headers_stand_alone` and `test_only_the_roles_severities_are_rendered`
   pass against the unfixed templates. `test_section_headers_stand_alone` asserts only
   `header in lines`; pre-change the headers *were* on their own lines (what was lost was
   the blank line before them), so the test cannot detect the thing it is named for.
4. **The reviewers' filing request went unactioned.** All three asked for the sync gap to
   be filed as its own issue per LESSON 4. It is not in the open list. The three WARN
   verdicts posted at 02:40:57–02:41:04; the merge landed at 02:55.

## Learnings

### For Future Issue Specs

**Fourth `no-files-section` stall — the action is older than three of them.**
#28, #29, #36 and now #37. `docs/learnings/pr-30.md` filed "put FILES TO CREATE /
FILES TO MODIFY in the issue template as required headings" on 2026-09-20;
`docs/learnings/pr-43.md` re-filed it on 09-27 with the words "a suggested action that
survives three occurrences is not a suggestion; promote it or delete it." It survived a
fourth. The cost here was seven days of wall-clock on a PR that was correct 17 minutes
after dispatch. Note that pr-43's own suggested-action list explicitly named #37 in the
sweep — the sweep fixed the issue body but nothing re-ran the gate until 09-27.

**Write acceptance criteria as invariants, not as literal expected output.** "Render as
five separate lines numbered 1–5" hard-codes a count that the fix itself changes, because
the filter the same issue asks you to correct selects three of the five. "Contiguous from
1 within each role's filtered set, with no gaps" is the same requirement and survives the
fix. An acceptance criterion that goes stale the moment the bug is fixed forces the agent
to choose between the criterion and the issue, and leaves the mismatch on the record.

**Naming the mechanism, the file and the line is what made this a 17-minute fix.** #37
did not say "the lists look wrong." It quoted the broken output, named `trim_blocks`,
cited `renderer/compose.py:47-51`, quoted the offending template lines, explained *why*
Pass 3 stayed green, and offered two resolutions with their blast radii. Compare the
delivery: correct on the first push, including a correction to the issue's own suggested
syntax. This and #36 are the two highest-fidelity specs in the repo; both produced
first-push-correct diffs. The shape is: symptom verbatim → mechanism → location →
resolutions ranked by blast radius → why existing tests missed it.

### For Future Domain Warnings

**`trim_blocks` deletes the newline after *every* block tag — `{% include %}` too.**
This is the warning that would have prevented the recurrence. PR #40 fixed the loop-tag
instance; **six days later issue #49 was filed for the same mechanism on `{% include %}`**,
in the same three templates, where the blank line between an include and the next heading
is eaten. #49's own opening line is "Found while fixing the list-collapse defect (issue
37). Same root cause family." A template in this repo may not close a content line with a
block tag unless it uses `+%}`, and that is a property of `templates/*.template.md`
generally, not of the three files that happened to be in one issue's scope.

**A test that renders one fixture context fences one path through the template.** The
templates branch on `deployment.surface` (five values), `rollback_available` and
`user_data_recoverable`. A shape test pinned to `surface: "server"` with both booleans
true exercises a minority of the lines it is protecting. Any future "assert the shape of
rendered output" work should parametrize the fixture over the branch variable before it
asserts anything, or state in the PR body which arms are unfenced.

**Prose in three files is not a rule; it is three copies of a rule.** The layout fence
here is a Jinja comment pasted into three templates plus a test whose role list is
`["engineer", "architect", "sre"]`. `cli/render.py:54` already maps a fourth role
(`deploy.template.md`) and `renderer/validators.py:303` already permits it, so that
template would inherit neither. The architect asked for the generalization — a static
check globbing `templates/*.template.md` for a block tag closing a content line without
`+%}`, and for `loop.index` under an in-loop `{% if %}` filter, in the style of
`tests/test_shared_partials.py:117`. That check is the thing that would have caught #49.
**This is LESSON 11's argument applied to templates: forbid the pattern with a check over
the glob, not with a comment in the files you happened to open.**

### For AGENTS.md

One edit made, to **LESSON 6**. Its third bullet already says that any premise about what
`main` currently looks like is unverified until you check it — and the agent applied that
to the issue's premises faithfully. The defect landed one level up: the agent asserted the
behaviour of `cli/sync.py` **in its own PR body** without opening it. LESSON 6 now extends
the same rule to the PR body, on the grounds that three machine reviewers read it and it
is the permanent record, so a claim written there is an assertion rather than narration.
The paragraph covers both failure modes seen here — behaviour of unopened code, and
counts / "these tests fail without the fix" — with `pytest --collect-only -q` named as the
way to get the number.

Deliberately **not** added: anything about `claimed-not-changed`. PR #40 is one of the two
data points that justified narrowing that gate to the `## Files` section only (commit
`f9cf18d`, PR #48); the script's own comment names this PR. A rule for it would describe a
world that no longer exists, and that section is law, not history — the same call
`docs/learnings/pr-43.md` made.

### Reusable Patterns

**Build the fixture so the regression is visible, not merely detectable.** `SHAPE_CONTEXT`
gives seven invariants with *interleaved* severities, so each role's matches begin at
source positions 2, 1 and 3. A `loop.index` regression therefore prints a gapped sequence
rather than a coincidentally-correct one. Choosing fixture data that makes the bug
inevitable — rather than data that merely permits the assertion — is the difference
between a test and a test that would have caught it.

**Check vacuity by restoring the old artifact, and report only what you re-ran.** The
agent did the right thing mechanically: `git checkout HEAD -- templates/`, re-render,
confirm the new tests fail. The reporting is where it broke — it generalized a spot-check
to all cases. The check is only worth its cost if the number you publish is the number you
observed, per-test.

**When the spec's suggested fix is wrong, use the right one and say which.** The issue
said `{%+ if %}`; the correct form is `+%}`. The agent used `+%}`, and wrote one sentence
in the PR body naming the difference. That sentence is why a reader of this learning does
not have to rediscover which modifier is which — a silent correction would have been just
as functional and worth nothing to the next agent.

**A WARN on an auto-merged PR has fifteen minutes here, and eight seconds on #43.** Three
reviewers converged on the `cli/sync.py` gap and all three asked for it to be filed. It is
still not filed. `docs/learnings/pr-43.md` recorded this same gap with #46 as the
precedent for the fix. **Convergence of all three reviewers on one finding is the
strongest signal this harness produces, and it currently has no landing path.**
